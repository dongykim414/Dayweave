# M5 Avatar Engine 구현 리포트

## 핵심 구조

Avatar를 완성 이미지가 아니라 semantic part ID의 조합으로 저장합니다. 사용자는 Hair
하나를 고르지만 registry는 이를 back/front visual로 해석할 수 있습니다. 화면과 DB는
asset 경로나 그림 방법을 알지 않습니다.

```text
Catalog: 앱에 무엇이 존재하는가
Ownership: 사용자가 무엇을 쓸 수 있는가
Selection: 지금 무엇을 착용했는가
```

M5는 모든 기본 Catalog item을 static Ownership으로 제공합니다. 미래 Store는 구매 성공
후 Ownership에 ID를 추가하면 되고 Selection이나 Renderer를 바꿀 필요가 없습니다.

## Renderer와 placeholder

완성 art가 없기 때문에 ImageGen 결과를 최종 asset처럼 사용하지 않았습니다. 동일한
320×320 좌표계의 code-native primitive를 registry에 두어 layer와 선택 engine을 먼저
검증합니다. Renderer는 ID별 조건문 없이 registry 결과를
`hairBack → body → bottom → top → hairFront → accessory` 순서로 그립니다.

최종 투명 PNG가 준비되면 semantic ID와 Catalog는 유지하고 visual registry mapping만
교체할 수 있습니다. 제작 규칙은 `docs/AVATAR_ASSET_GUIDE.md`에 분리했습니다.

## Persistence와 빠른 선택

SQLite v3 `avatar_config`는 `singleton_key = 'current'` primary key를 사용합니다. 선택을
몇 번 바꿔도 upsert되는 row는 하나입니다. Web preview는 localStorage 단일 key로 같은
Repository contract를 구현합니다.

선택 즉시 UI를 바꾸되 DB write는 queue로 직렬화합니다. A와 B를 빠르게 눌러도 A 저장
뒤 B 저장 순서를 유지합니다. 저장이 실패하면 단순히 직전 UI 값이 아니라 마지막으로
성공한 persisted config로 rollback합니다.

## Fallback

DB에는 문자열이 있으므로 앱 update로 Catalog item이 제거될 수 있습니다. Mapper는 각
slot을 독립적으로 확인해 잘못된 Hair만 기본 Hair로 바꾸고 유효한 Top 등은 유지합니다.
복구된 config는 initial load에서 다시 single row에 저장됩니다.

## 검토한 대안

- 완성 캐릭터 한 장 저장: 조합과 Store 확장을 막아 제외
- Hair front/back을 별도 선택: 사용자 모델이 복잡해져 Hair definition 내부 layer로 처리
- AsyncStorage 추가: 이미 SQLite lifecycle이 있어 dependency를 늘리지 않음
- 저장 버튼: 가벼운 꾸미기 UX에 마찰이 커 즉시 preview+save 선택
- global state: 현재 Avatar 탭에서만 소비하므로 feature hook으로 충분

## 검증과 후속 확인

Pure tests는 default config, invalid fallback, ownership, nullable accessory, registry layer,
mapper와 Web single-key persistence를 확인합니다. 실제 Android의 v2→v3 migration,
single row, 재실행 복원과 layer 육안 검증은 사용자 요청대로 MVP 직전 통합 QA에서
M2~M5 검증과 함께 수행합니다.

최종 자동 검증에서는 lint, typecheck, version/dependency check, 15 suites·51 tests,
12개 Web static route 및 1,326-module Android JS export가 통과했습니다. `/avatar`는 HTTP
200을 반환했습니다. Codex Browser의 kernel asset path 오류 때문에 자동 screenshot은
실행하지 못했으며, 이는 앱 실패가 아닌 도구 환경 제약으로 하네스 기록에 분리했습니다.
