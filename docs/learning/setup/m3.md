# M3 Timeline 구현 리포트

## 무엇을 만들었나

Timeline 탭을 현재 월의 7열 달력으로 바꾸고, 이전·다음 월 이동, 오늘과 선택 날짜,
Diary가 있는 날짜의 Photo/Mood marker, 선택 날짜의 read-only preview를 연결했습니다.

## Calendar 계산을 UI에서 분리한 이유

월의 첫 요일, 윤년, 앞뒤 overflow와 5/6주 여부는 화면 표현과 별개의 날짜 규칙입니다.
이를 pure function으로 두면 React Native를 띄우지 않고 1월·12월 연도 경계, 윤년 2월,
일요일/토요일 시작 월을 테스트할 수 있습니다. 날짜는 M1과 같은 device-local
`YYYY-MM-DD`이며 UTC 문자열로 왕복하지 않아 하루가 밀리지 않습니다.

## 범위 API를 선택한 이유

Repository에 월 전용 `getByMonth` 대신
`listRecordsByDateRange(startInclusive, endExclusive)`를 추가했습니다. 예를 들어
2026년 9월은 `>= 2026-09-01`, `< 2026-10-01`입니다. 다음 달 1일을 제외하는 반열린
범위는 월말이 28·29·30·31일인지 별도로 계산하지 않고 향후 주간 조회에도 재사용됩니다.

Native SQLite는 Diary와 Photo metadata를 `LEFT JOIN` 한 번으로 가져옵니다. 날짜 셀마다
Photo query를 호출하는 N+1 구조가 아닙니다. `entry_date UNIQUE`가 이미 range index 역할을
하고 Photo 관계에도 UNIQUE index가 있어 중복 index나 migration은 추가하지 않았습니다.
현재 Diary는 텍스트 규모가 작고 한 달만 읽으므로 별도 Timeline read table도 만들지
않았습니다.

## Marker와 Mood 구조

셀은 `사진 → Mood → record dot` 중 하나만 표시합니다. M2의 display image를 24px 영역에
렌더해 thumbnail file을 새로 만들지 않습니다. Mood는 Calendar가 ID를 emoji로 바꾸지
않고, Today와 공유하는 `MoodVisual`이 active Mood Pack을 해석합니다. 따라서 Mood Pack이
바뀌어도 Timeline domain을 고칠 필요가 없습니다.

## 선택과 비동기 상태

처음에는 오늘을 선택합니다. 이전·다음 달 버튼은 이동한 달의 1일을 선택합니다.
overflow 날짜를 누르면 그 정확한 날짜를 선택하면서 표시 월도 함께 바뀝니다. 선택
Diary는 월간 결과에서 찾으므로 추가 query가 없습니다.

월이 바뀌면 지난 결과를 비워 잘못된 달의 기록이 잠깐 보이는 flicker를 막습니다.
사용자가 버튼을 빠르게 누르면 request sequence가 가장 최근 요청만 반영합니다.
Timeline 탭으로 다시 돌아올 때도 focus effect로 Today에서 저장한 변경을 다시 읽습니다.

## 다른 선택지와 비용

- 날짜 library: timezone API가 풍부하지만 이 범위에는 dependency 비용이 더 커서 제외
- 월 전용 SQL: 간단하지만 주간 범위에 재사용하기 어려워 date-range contract 선택
- Cell별 query: 구현은 직관적이나 월 기록 수만큼 query가 늘어 제외
- 별도 thumbnail: 큰 목록에서 유리할 수 있으나 저장·정리 pipeline이 늘어 M2 결정을 유지
- Global state: 두 개의 화면 상태와 repository load에는 feature hook으로 충분해 제외

## 직접 확인하는 방법

```bash
pnpm test
pnpm lint
pnpm typecheck
pnpm build:web
```

자동 테스트는 grid, rollover, 윤년, 범위 제외와 Web repository mapping을 확인합니다.
Native SQLite join, 실제 사진 marker, 작은 Android 화면, 앱 종료 후 복원과 빠른 버튼 입력은
실제 기기 또는 emulator에서 CASE 1~15로 최종 확인해야 합니다.

현재 검증에서는 9 suites/31 tests, Web 11개 route export와 Android JavaScript 1,308개
module bundle이 통과했습니다. Android bundle은 Windows 환경의 Hermes 실행 제약을 피해
`--no-bytecode`로 확인했으므로 실제 Native 실행을 대체하지 않습니다.

## M4에 이어지는 결정

M4에서 Mood Pack 선택이 추가되어도 `MoodVisual` resolver만 active pack을 사용하면 됩니다.
Timeline은 read-only를 유지하며 Diary 상세·수정·삭제를 M3에 소급해 섞지 않습니다.
