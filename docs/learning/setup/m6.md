# M6 Personalization 구현 리포트

## 구조

Theme과 Mood Pack 각각 Catalog, static Ownership, 현재 Selection을 분리했습니다. 선택은
`PersonalizationSettings`에 semantic ID로만 저장되고 실제 색상과 Mood visual은 각
registry가 해석합니다.

## Provider 순서

DB migration 뒤 설정을 먼저 읽고, 그 ID로 ThemeProvider와 MoodPackProvider를 구성한
다음 Router를 렌더합니다. 따라서 각 화면이 저장소를 읽거나 Theme/Mood별 조건문을
가질 필요가 없습니다.

## 즉시 적용과 저장

가벼운 설정 UX에 맞춰 optimistic apply와 순차 저장을 사용했습니다. 빠르게 여러 번
선택해도 write 순서를 보장하고 최신 저장이 실패하면 마지막 성공 설정으로 돌아갑니다.

## 표현과 데이터 분리

Cat Pack을 선택해도 DiaryEntry의 `happy` 같은 값은 유지됩니다. MoodPackProvider가
`happy`를 현재 pack의 visual로 바꾸며 누락 visual은 Default Pack으로 fallback합니다.

## 대안

- 화면별 ID 조회는 상태 불일치 때문에 제외했습니다.
- 별도 Theme/Mood table은 두 값뿐인 local user 설정에 과해 한 설정 행을 선택했습니다.
- 전역 상태 라이브러리는 Provider와 repository로 충분해 추가하지 않았습니다.
- 잠금·구매 UI는 Store 범위이므로 owned-only 목록을 사용했습니다.

Android migration·재실행·빠른 선택은 MVP 통합 QA에서 확인합니다.

최소 자동 검증은 typecheck, lint, 17 suites·56 tests와 `/me` Web HTTP 200까지
확인했습니다. Browser screenshot은 Codex runtime 경로 오류로 수행하지 못했습니다.
