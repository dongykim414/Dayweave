# M0 Foundation 학습 가이드

이 경로는 M0 Foundation에서 **무엇을 바꿨는지**만 기록하는 변경 로그가 아닙니다.
각 결정의 이유, 고려한 대안, 선택하지 않은 이유, 직접 확인하는 방법을 함께 설명하는
학습 자료입니다.

코드를 전부 이해한 뒤 PR을 병합할 필요는 없습니다. 다만 아래 세 가지는 설명할 수
있을 정도로 이해하는 것을 목표로 합니다.

1. M0에서 왜 실제 다이어리 CRUD보다 구조를 먼저 만들었는가?
2. 새 기능을 어느 폴더에 넣어야 하는가?
3. AI가 완료했다고 말할 때 어떤 증거를 확인해야 하는가?

## M0를 한 문장으로 이해하기

M0는 “사용자가 일기를 저장할 수 있는 버전”이 아니라, 앞으로 일기 기능을 안전하고
일관되게 쌓을 수 있도록 **길, 구역, 규칙과 검사 장치**를 만든 버전입니다.

건물에 비유하면 다음과 같습니다.

- `app/`: 사용자가 각 공간으로 이동하는 복도와 문
- `src/features/`: 실제 기능이 들어갈 방
- `src/shared/`: 여러 방에서 공통으로 사용하는 부품
- Theme: 모든 방이 따르는 색상·간격·글꼴 규칙
- `AGENTS.md`: 작업자가 지켜야 할 현장 규칙
- CI: 규칙을 어긴 결과물이 들어오지 않게 검사하는 출입구

## 변경 전과 변경 후

### 변경 전

- 일정/Todo 앱을 설명하는 README와 MVP 문서
- `src/app/index.tsx` 한 화면
- 화면 내부에 직접 작성한 HEX 색상과 스타일
- npm lockfile
- 다이어리 도메인 확장 규칙이 코드와 저장소 문서에 정착되지 않은 상태

### 변경 후

- 감정 + 한 줄 + 선택 사진 중심 개인 다이어리로 제품 기준 통일
- 오늘·타임라인·아바타·내 정보 4탭
- route와 feature screen 분리
- Sky Theme와 ThemeProvider
- 공용 UI primitive 다섯 개
- semantic Mood ID와 파츠형 Avatar 타입
- pnpm lockfile과 CI
- 제품·디자인·아키텍처·개발·로드맵·AI 규칙 문서

## 이 문서를 공부하는 방법

각 장을 읽을 때 다음 순서로 확인하면 좋습니다.

1. 먼저 “문제”만 읽고 스스로 해결 방법을 생각합니다.
2. “선택한 방법”과 자신의 생각을 비교합니다.
3. “다른 선택지”에서 장단점을 확인합니다.
4. 연결된 실제 파일을 VS Code에서 엽니다.
5. “직접 확인” 명령을 실행해 설명과 결과가 일치하는지 봅니다.
6. 마지막 질문에 자신의 말로 답합니다.

AI가 작성한 문서를 정답으로 외우기보다, **결정과 근거가 실제 코드·명령 결과와
일치하는지 검증하는 습관**을 만드는 것이 이 자료의 목적입니다.
