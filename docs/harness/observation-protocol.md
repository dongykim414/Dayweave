# Agent Observation Protocol

## 목적

AI 코딩 Agent가 작업을 어떤 근거로 탐색, 계획, 구현, 검증하고 완료하는지
관찰 가능한 행동을 통해 확인합니다.

## 관찰 단계

### 1. 요청 해석

- 최종 결과를 어떻게 이해했는가
- 명시된 성공 조건은 무엇인가
- 작업 범위에 영향을 주는 가정이 있는가

### 2. 탐색

- 어떤 파일과 디렉터리를 확인했는가
- 각 대상을 확인한 이유는 무엇인가
- 코드와 설정에서 무엇을 발견했는가

### 3. 계획

- 어떤 순서로 작업할 것인가
- 어떤 파일을 수정할 것으로 예상하는가
- 어떤 방식으로 결과를 검증할 것인가

### 4. 구현

- 실제로 수정한 파일은 무엇인가
- 각 변경의 목적은 무엇인가
- 발견한 사실로 인해 계획이 변경됐는가

### 5. 검증과 실패 대응

- 실행한 test, lint, typecheck, build 명령은 무엇인가
- 각 명령은 성공했는가
- 실패 메시지에서 확인한 직접적인 단서는 무엇인가
- 무엇을 수정하고 어떤 검증을 다시 실행했는가

### 6. 완료 판단

- 어떤 증거를 근거로 완료했다고 판단했는가
- 실행하지 않은 검증은 무엇이며 이유는 무엇인가
- 확인하지 못한 부분과 남은 위험은 무엇인가

## 작업 요청 템플릿

```text
docs/harness/observation-protocol.md를 읽고 관찰 모드로 진행해줘.

내부 사고과정을 설명하지 말고, 관찰 가능한 행동과 근거만 단계가 발생할 때마다
짧게 알려줘. 코드를 수정하기 전에는 탐색에서 발견한 사실, 수정 계획, 검증 계획을
먼저 알려줘. 오류가 발생하면 바로 수정하기 전에 오류의 직접적인 단서와 다음 확인
대상을 알려줘.

작업이 끝나면 변경 파일, 실행한 검증과 결과, 남은 위험을 정리하고
docs/harness/templates/run-log.md 형식의 실행 로그를 작성해줘.

이번 작업:
[여기에 실제 작업을 작성]
```

## 제한

- 숨겨진 내부 사고과정이나 장문의 독백을 요구하지 않습니다.
- 실행하지 않은 명령이나 확인하지 않은 동작을 실행한 것처럼 기록하지 않습니다.
- 오류를 숨기거나 성공으로 바꾸어 표현하지 않습니다.
- 테스트를 통과시키기 위해 요구사항을 약화하지 않습니다.
